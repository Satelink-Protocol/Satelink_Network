# ADR-001: Rail-Agnostic Core; x402-on-Base Is Rail #1, Not the Architecture

- **Status:** Accepted (2026-07-20)
- **Deciders:** vNext architecture reset

## Context

The vNext success criteria require "no dependency on x402 success" while all verified machine-settlement evidence in this project's history is x402-on-Base via the CDP facilitator (real mainnet inbound settlements Jul 9–10 2026 [measured]; live merchant stack [code: `apps/api/src/payments/x402/`]). These pull in opposite directions: build on the only rail that demonstrably works, without marrying it.

Additional facts:
- A settlement-adapter abstraction already exists in-repo and includes Shadow (no-broadcast) test doubles [code: `apps/api/src/settlement/adapters/ISettlementAdapter.js` family].
- A second live settlement mechanism exists: permissionless USDT deposits to RevenueVaultV2 on Polygon [code: vault `0x577D…BaCEF`, PR #234].
- Facilitator concentration risk is real: CDP could occupy the aggregator seat or change fee terms (probability UNKNOWN — see `../02_MARKET_VALIDATION/SEAT_ANALYSIS.md`).

## Decision

1. The core engine speaks only the `RailAdapter` interface (`challenge / verifyAndSettleIn / payOut / verifyOut`); no core module imports x402 SDKs directly.
2. `x402-base` is Rail #1 (Phase 1): inbound wraps the existing merchant stack; outbound is ported from x402-kit.
3. `erc20-polygon` (USDT + RevenueVaultV2) is Rail #2, delivered in Phase 3 as the proof of rail independence — one full spread event settled entirely on it.
4. Every rail ships with a Shadow implementation (full path, no broadcast), inheriting the one proven-good legacy pattern.

## Consequences

- Positive: rail death ≠ system death; test paths without money; new machine-payment protocols become adapters, not rewrites.
- Negative: an interface layer over a single implementation is speculative generality *until Phase 3 delivers Rail #2* — the ADR is only honest if B-14 actually ships; if Phase 3 drops it, this ADR must be revisited, not quietly ignored.
- Constraint accepted: Phase 1–2 revenue remains 100% x402-dependent. Stated risk, bounded by Phase-1 caps.

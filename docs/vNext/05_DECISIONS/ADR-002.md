# ADR-002: RPC Is Demoted from Product to Supplier Row #1

- **Status:** Accepted (2026-07-20)
- **Deciders:** vNext architecture reset

## Context

Satelink's identity for ~2 years was "machine-commerce RPC gateway." Measured outcome of that identity:
- 496,273 req/24h of free RPC traffic; p50 46ms [measured 2026-07-16] — the *capacity* works.
- ~$0 real revenue; all pre-2026-07-11 revenue was founder test data [measured, war room]; 8 conversion PRs moved the number ~nothing [measured].
- List price was measured at 965% above market median with zero-commitment as the only advantage [code+measured: pricing_intelligence, PR #242].
- The RPC-as-product ecosystem fails the admission gate (Q4/Q5/Q8: human signup demand, fiat settlement) [scorecard].

Meanwhile the vNext mission requires that no single workload's failure kills the system.

## Decision

1. RPC ceases to be the product. It becomes **WorkloadAdapter `rpc`, supplier row #1** in the supply index — Satelink's own gateway capacity [code: `apps/api/src/workloads/rpc_gateway/`] listed, probed, scored, and priced like any external supplier.
2. Self-supply gets **no routing privilege** and an honest internal unit cost (> 0, config + ADR to change). If an external supplier beats it, the router buys external.
3. The legacy free `/rpc` surface keeps running (it is the discovery pool and costs nothing incremental), but no new RPC-product features are built. The `$500/hr` RPC revenue target is retired as a commitment.
4. The RPC adapter is *deletable*: if its spread contribution is zero once alternatives exist, it can be retired without touching core.

## Consequences

- Positive: "no dependency on RPC success" becomes structural; the sunk RPC investment is salvaged as real, working supply rather than defended as identity; pricing becomes formula-inherited (cost + margin) instead of the measured-uncompetitive invented price.
- Negative: emotionally, this writes off the founding thesis — this ADR exists so that the write-off is explicit, dated, and never relitigated implicitly through feature creep on the legacy surface.
- Guard: any PR adding RPC-product features (new tiers, new RPC-specific funnels) must cite a reopened scorecard, otherwise it violates this ADR.

## Inspection and STOP evaluation

> STOP if: flaky testnet resets break determinism (report mitigation).

**Not triggered, but not yet observable either.** No testnet keys exist in this environment, so a testnet reset couldn't be observed. The design keeps determinism anyway:

- **The paper loop is fully deterministic and doesn't depend on the testnet.** It uses a fixed clock, sequential ids, a scripted model, the paper venue (MockBroker), and a fresh database with all migrations 001–030. **Five consecutive local runs** were green, and the run report was **byte-identical every time** apart from the random trace ids (sha256 prefix `8f3597c49190`, re-confirmed after the step labels were renamed).
- **The testnet leg** asserts only what a reset can't change: a far-from-market LIMIT order is acknowledged and then cancelled through the OMS, and a complete receipt is produced. It doesn't rely on balances, fills or market prices.
- **Testnet failures are classified** (`classifyTestnetFailure`), so a red night says **why**:
  - **`TESTNET_KEYS_REJECTED`** (-2015 / -2014 / -1022, auth): a reset is suspected. Regenerate the keys at testnet.binance.vision and update the environment secrets.
  - **`TESTNET_BALANCE_MISSING`** (-2010, insufficient balance): a reset is suspected (balances wiped).
  - **`TESTNET_REGION_BLOCKED`** (451/403, "restricted location"): the runner's region was refused. GitHub-hosted runners are US-based, and audit 08 found Binance geo-blocks US egress for the live API. Whether the **testnet** blocks US runners is **unverified**. The mitigation would be a self-hosted runner in a permitted region (the same egress question as B-08).
  - **`TESTNET_UNAVAILABLE`** (connection, ambiguous, rate limit): transient. Re-run once; two in a row is an incident.
  - **`TESTNET_UNEXPECTED`**: treated as a regression.
- **Mitigation policy:** a classified testnet reset doesn't count against code health, but it **also doesn't count as a green night**. The 5-consecutive-green clock restarts after a human fixes the environment.

## Failure injection

| Injected failure | Expected | Asserted |
|---|---|---|
| Venue times out **after** accepting | UNKNOWN, never resent; UNKNOWN-age alert fires after 5 min; reconciler finds the order; the alert resolves | dispatcher `unknown` → collector count 1 → **TradingUnknownOrderAging fires** → reconciler → `acknowledged` → count 0 → **resolves**; exactly one venue order |
| Stale market data (provider flag) **and**, separately, an old quote | risk REJECT before the venue | `RISK_STALE_MARKET_DATA` for each, independently |
| Global kill switch (admin) | alert fires; risk REJECT; released afterwards | **TradingGlobalKillSwitch fires**; `RISK_KILL_SWITCH` |
| Mandate revoked | acceptance refused | `MANDATE_*` reason; no order rows; a dispatcher run reaches the venue **0 times** |
| Broker unreachable for 2 min | marked down; alert | **TradingBrokerUnreachable fires** |

**Mutation checks across the stack (7, all caught by the E2E):**
- risk ignoring the stale flag;
- risk ignoring quote age (both survived at first, because one injection tripped both checks, so each is now injected separately);
- risk ignoring kill switches;
- a receipt that's never complete;
- a disabled reconciler;
- backtest pass criteria ignored.

## Nightly job (`.github/workflows/trading-e2e-nightly.yml`)

**Triggers:** `schedule` 02:00 IST, plus `workflow_dispatch`. **Never** on push or pull_request, so it can't affect PR checks.

**Token:** `permissions: contents: read`.

**Jobs:**
- **paper-loop:** an ephemeral Postgres service container, a guard database, then the E2E with a JSON report artifact.
- **binance-testnet** (after paper-loop):
  - runs in the GitHub **Environment `trading-testnet`**, so the secrets `BINANCE_TESTNET_API_KEY` / `BINANCE_TESTNET_API_SECRET` are scoped to it;
  - **fails with `TESTNET_SECRETS_MISSING`** rather than skipping, so a green night always means the testnet was exercised;
  - uploads the receipt as an artifact.

**Never production:**
- no deploy, Railway, Vercel or `DATABASE_URL` step;
- only the testnet host;
- the adapter refuses production while `LIVE_TRADING` is locked;
- no `| tail` masking, so failures fail.

A test (`trading_e2e_support.test.js`) enforces these rules.

**Non-breaking (brief §6):** a new file only; existing workflows are unchanged.

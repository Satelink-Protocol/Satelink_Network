## 1. Canonical vs Legacy

| Surface | Path | Verdict | Evidence |
|---|---|---|---|
| **Canonical frontend** | `apps/web` | KEEP | Next `^15.5.0`, depends on `@satelink/ui` (`apps/web/package.json`), deployed to `app.satelink.network`. 8 route pages, all on the v2 design system. |
| **Design system (SSOT)** | `packages/ui` (`@satelink/ui`) | KEEP | `main: src/index.ts`; exports 13 dashboard primitives + 11 shadcn/Radix primitives. Header comment declares it "single source of truth". |
| **Legacy frontend** | `apps/dashboard` | RETIRE | 112 page files, **0** imports of `@satelink/ui` (`grep -rl "@satelink/ui" apps/dashboard/src` → 0), `package.json` declares `"next": "^0.4.1"` (invalid/unbuildable), not referenced by any `vercel.json` / `railway.json`. Maintains its own `components/ui` fork. |

**Conclusion:** `apps/web` + `packages/ui` are the future. `apps/dashboard` is dead weight
and the primary source of fragmentation. See `LEGACY_FRONTEND_PLAN.md`.

## 3. Duplicated UI components (the core problem)

`apps/web/src/components/ui/*` is a **drifted fork** of `packages/ui/src/components/ui/*`.

```

```

Every overlapping file has drifted. **None of these is imported by any page.** The only
importers are:
- `apps/web/src/components/ui/sidebar.tsx` (self-referential within the dead dir)
- `apps/web/src/components/shadcn-trial/CustomerZeroCard.tsx` (a trial card)

`apps/web/src/components/ui/chart.tsx` is the **only** primitive with no `packages/ui`
equivalent (recharts wrapper).

**→ `apps/web/src/components/ui/` is dead duplication.** Disposition in `DESIGN_SYSTEM_CONSOLIDATION.md`.

## 4. The two-tier component story in apps/web

`apps/web/src/components/satelink-os/` is the **v1 bespoke design system** (CSS-modules,
~80 files: `shell/AppShell`, `tables/DataTable`, `layout/Grid`, `charts/*`, `theme/tokens`,
etc.). It predates `@satelink/ui`.

- **OS pages have fully migrated off it** — none of `os/*` import `satelink-os`.
- **Only `admin/command-center`** still imports it, and deliberately so: for *domain
  visualizations* (`TopologyDiagram`, `RevenueProjectionChart`, `LeadPipelineTable`,
  `CustomerZeroPanel`, `LiveEventStream`, `AutomationHealth`, `FilterPanel`). Its header
  comment correctly classifies these as "content/features, not chrome." Chrome
  (`DashboardShell`, `KPIGrid`, `StatCard`, `DataTable`) already comes from `@satelink/ui`.

**Migration candidate:** extract the ~7 domain-viz components command-center actually uses
into `@satelink/ui` (or a `@satelink/charts` subpath), then delete the rest of `satelink-os`.

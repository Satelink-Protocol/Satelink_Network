# ORG STRUCTURE — ENTERPRISE OS V2

## Mission

Turn Satelink from a queue-driven AI workforce into a revenue-focused,
security-first, wake-on-demand enterprise operating system.

## Active Runtime Roster

### CEO
- Final escalation gate
- Founder-facing status owner
- Approval boundary owner
- Wakes only for cross-division escalation, blocked approvals, or unresolved
  `REV-1` / `SEC-1` events

### ENGINEERING_COMMANDER
- Owns engineering execution in the initial rollout
- Temporarily absorbs:
  - `QA_COMMANDER`
  - `DEPLOYMENT_COMMANDER`
  - `SRE_COMMANDER`
- Handles:
  - deployment failures
  - test failures
  - runtime incidents
  - reliability regressions

### ECONOMY_COMMANDER
- Owns revenue growth and cash conversion
- Uses role packs:
  - `DEMAND_COMMANDER`
  - `CONVERSION_COMMANDER`
  - `RETENTION_COMMANDER`
- Handles:
  - collected USDT health
  - active paying wallets
  - recurring deposits
  - customer zero lifecycle
  - machine and protocol customer growth

### SECURITY_COMMANDER
- Owns secrets, treasury protection, and adversarial readiness
- Uses role packs:
  - `TREASURY_GUARDIAN`
  - `RED_TEAM`
  - `BLUE_TEAM`
- Handles:
  - secret exposure
  - treasury mismatch
  - deployment security review
  - adversarial challenge and response

### AUTONOMY_COMMANDER
- Owns founder-independence execution
- Mission: every founder action must eventually become an automation
- Converts manual work into:
  - automation
  - guardrails
  - accepted manual exceptions

## Dormant Governance

### BOARD
- Dormant in initial rollout
- Used only when high-control governance review is explicitly required
- Not a routine runtime participant

### RISK_AGENT
- Dormant in initial rollout
- Activated only by explicit governance threshold or future phase policy
- Never wakes on routine delivery, monitoring, or customer flow

## Role Packs Only In Initial Rollout

These are named responsibilities, not always-on agents:
- `QA_COMMANDER`
- `DEPLOYMENT_COMMANDER`
- `SRE_COMMANDER`
- `DEMAND_COMMANDER`
- `CONVERSION_COMMANDER`
- `RETENTION_COMMANDER`
- `TREASURY_GUARDIAN`
- `RED_TEAM`
- `BLUE_TEAM`

## Ownership Law

- One open event has one accountable commander.
- Cross-functional help comes through role packs or escalation, not parallel
  unowned activation.
- No queue slots.
- No rotational law.
- No one-agent heartbeat supervision.
